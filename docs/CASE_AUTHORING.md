# 사건 작성 가이드

Monologue Gaze 의 사건 하나는 `cases/cNN-이름.js` 파일 하나다. 파일은 `MG.registerCase({...})` 를 한 번 호출한다.
엔진(`js/engine.js`)과 스타일(`css/`)은 모든 사건이 같이 쓴다. 사건 파일은 **데이터만** 담는다.

작성이 끝나면 반드시:

```
node tools/validate.js cases/cNN-이름.js   # 형식 + 추적 경로
node tools/smoke.js cases/cNN-이름.js      # 모든 화면을 실제로 그려 본다
```

`결과: PASS` 와 `SMOKE OK` 가 나와야 한다. 경고(△)도 가능한 한 없앤다 (특히 「검색 지름길」). 참고용 완성본은 `cases/c00-cheongun.js` (튜토리얼).

---

## 1. 게임의 핵심 — "쫓아가는" 추리

- 플레이어는 형사다. 직접 걸어 다니지 않고 **그 시대의 기록**(신문, 진술서, 편지, 장부, 녹취록, 미니홈피…)을 뒤진다.
- 처음엔 사건 개요 한 장과 단어 몇 개만 준다. **수첩에 적힌 단어로만** 자료실을 검색하고, 사람을 찾아가 물어볼 수 있다. 단서 하나가 다음 단서를 연다. 이게 "추적"이다.
- 문서 속 `[[단어]]` 는 눌러서 수첩에 적는 단어(= 새 실마리)다. 문단·표의 행·말풍선은 전부 ✎ 로 "메모"할 수 있다. **어떤 메모가 증거가 되는지는 플레이어에게 보이지 않는다.** 쓸모없는 문장도 똑같이 적힌다.
- 보고서는 객관식이 아니다. 범인은 **수첩에 적은 인물 중에서** 고르고, 주장마다 **메모 하나를 증거로** 붙인다. 전부 맞아야 사건이 종결된다. 한 군데만 틀리면 "딱 한 군데가 어긋난다"고만 알려 준다.
- 정답(진범·진상)은 **정해져 있지만 어떤 문서에도 대놓고 적혀 있지 않다.** 자백, "범인은 ○○다" 같은 문장, 결론을 요약한 문서는 금지. 진상은 서로 다른 기록 두세 개를 겹쳐 봐야만 보인다. 결말(epilogue)은 종결 뒤에만 나온다.

## 2. 파일 구조

```js
MG.registerCase({
  id: 'c01', no: 1,                    // id 는 파일명 앞부분과 같게
  region: 'overseas',                  // 'domestic' | 'overseas' (튜토리얼만 kind:'tutorial')
  title: '화이트채플의 편지',            // 기록실 폴더에 붙는 제목 (짧게)
  year: '1888', place: '런던 이스트엔드 (가상 지명)',
  motif: '모티프: 화이트채플 연쇄살인',   // 폴더에 손글씨로 적힌다
  length: '약 30분',
  stars: 3,                            // 난이도 3·4·5 (11절). 튜토리얼은 없음
  graphic: false,                      // (선택) 잔혹한 내용·강한 묘사가 있으면 true → 빨간 별 + 표지에 「혐오감 주의」 + 첫 열람 경고
  warn: '…',                           // (선택) graphic 사건의 첫 열람 경고 문구 (무엇이 들어 있는지 한 문장)
  frame: 'papers',                     // 'papers'(종이 서류철, 기본) | 'crt'(2000년대 모니터) | 'laptop'(2020년대)
  mood: { light: 'gas', fx: 'fog', amb: ['wind', 'bell'], line: '…' }, // (선택) 사건의 공기 — 조명·날씨·배경음·여는 글 (12절)
  live: { start: [2024, 3, 8, 22, 40], deadline: { at: 2880, label: '…' } }, // (선택) 실시간 수사 — 시계가 가는 지금의 사건 (13절)
  tag: '**증거철 01** · 런던 경시청 H 분서', // (선택) 화면 아래 증거물 꼬리표 (HTML 태그 대신 **굵게**)
  me: '서윤',                          // (선택) 말풍선 me:true 를 메모할 때 앞에 붙는 이름 (기본 '나')
  disclaimer: '…',                     // (선택) 수첩 맨 아래 문구
  emptyRead: '…',                      // (선택) 아무것도 안 열었을 때 읽기 칸 문구
  brief: { title: '사건 개요', no: '사건번호', lines: [['피해자', '…[[단어]]…'], ...], scrawl: '형사의 빨간 펜 한 줄' },
  start: ['k_a', 'k_b'],               // 처음부터 수첩에 적혀 있는 단어 (brief 에 [[ ]]로 나오는 것들)
  tips: ['…'],                         // (선택) 수첩 첫 장에 연필로 적힌 힌트. 튜토리얼 말고는 0~2개
  sources: [ … ],                      // 조사 도구 (아래 3절)
  keywords: { … },                     // 단어 (4절)
  docs: { … },                         // 문서 (5절)
  people: { … },                       // 탐문 대상 (6절)
  art: { … },                          // 그림 (8절)
  artStyle: '…',                       // 이미지 프롬프트 공통 스타일 문단 (영어)
  css: `…`,                            // (선택) 사건 전용 CSS. 반드시 [data-case="c01"] 로 시작하는 선택자만
  solution: { … },                     // 정답 (7절)
});
```

## 3. 조사 도구 (sources)

탭으로 보인다. 시대에 맞는 이름을 붙인다 (예: 「이스트엔드 스타 자료실」, 「H 분서 진술서철」, 「탐문」, 「동네 지도」).

| type | 하는 일 | 필수 속성 |
|---|---|---|
| `archive` | 검색창. 입력한 말이 단어의 label/alias 와 맞으면, 그 단어를 `find` 에 가진 문서가 뜬다. 수첩에 적은 단어는 일부만 쳐도 되지만, 아직 모르는 단어는 label/alias 를 온전히 쳐야 찾힌다(추측 검색으로 사슬을 건너뛰지 못하게). | `start: [문서id]` (처음부터 보이는 문서, 선택) |
| `list` | 문서 목록(서류철, 우편함, 유류품 상자, 메신저 대화방). `need` 가 채워진 문서가 나타난다. | — |
| `people` | 탐문. 인물을 고르고 수첩의 단어로 질문한다. | — |
| `map` | 지도 위 점을 누르면 문서가 열린다. | `art`(지도 SVG 키), `spots:[{id,label,x,y,doc,need}]` (x,y 는 %) |
| `cipher` | 기호→글자 대응을 채워 암호문을 푼다. | `cipher`(암호문 문자열), `key`({기호:글자}), `given`(미리 알려 줄 대응), `keep`(그대로 둘 문장부호), `intro`, `solved`(풀면 보이는 블록), `reward:{keys:[]}`, `solveNeed`(검사기용: 풀 수 있게 되는 조건) |

| `timeline` | **사건 재구성.** 사건 카드를 ▲▼로 옮겨 순서를 맞춘다. 흩어진 기록(우유 수거 장부, 우편 배달 일지, 통화 기록…)을 모아야 순서가 보이게. | `events:[{id,t}]`(**정답 순서대로** 적는다. 화면에서는 섞여 나온다), `slots:['21:00',…]`(선택, 칸마다 붙는 시각·날짜), `title`, `intro`, `solved`, `reward:{keys}`, `solveNeed`, `ok`(선택, 풀었을 때 알림) |
| `compare` | **대조 감정.** 증거 하나와 시료 여럿 가운데 일치하는 것을 고른다 (필적, 족적, 타이어 자국, 도료, 섬유, 목소리, 지문 특징점…). | `sets:[{id,title,meta,need,intro,evidence:{label,t,art},q,options:[{id,label,t,art}],answer,hint,solved,reward:{keys},solveNeed}]` |
| `query` | **기록 조회.** 번호·이름·날짜를 정확히 넣어 대장을 조회한다 (차량 등록, 전화번호부, 주민 기록, 숙박부 색인, 통화 내역, 수하물 번호…). 값은 다른 기록에서 알아내야 한다. | `fields:[{id,label,placeholder}]`, `records:[{match:{칸id:['값','다른 표기']}, doc:'문서id', need:[…], keys:[…]}]`, `none`(결과 없음 문구), `button` |
| `photo` | **정밀 관찰.** 현장 스케치·감식 사진을 눌러 숨은 지점을 찾는다. 찾으면 그 지점의 기록이 열린다. | `scenes:[{id,title,meta,need,art,intro,spots:[{id,x,y,r,label,body,keys,need}]}]` (x,y 는 %, r 은 반지름 % — 기본 7) |
| `request` | **영장·공문 신청** (live 사건 전용, 13절). 소명 메모를 붙여 올리면 시간이 지나 회신이 온다. | `items:[{id,title,kind,to,target,what,need,why,deny,eta,doc,keys,feed}]` |
| `feed` | **팀 단톡방** (live 사건 전용, 13절). 시간이 흐르거나 조건이 채워지면 새 말이 온다. | `items:[{id,at,need,who,msg,me,f,doc,att,keys}]` |

**새 조사 방식 쓰는 법** — 최소 예시: `docs/examples/methods-example.js`
- 문서는 모두 `c.docs` 에 두고, `query` 문서만 `src` 를 그 조회 도구로 둔다 (목록에는 안 뜨고 조회해야 나온다).
- `timeline`·`compare`·`cipher` 는 **정답을 알 수 있게 되는 조건**을 `solveNeed` 에, `query` 는 넣을 값을 알게 되는 조건을 `record.need` 에 적는다. 둘 다 검사기용이다 (화면에서는 막지 않는다).
- `compare` 는 ★4 이상에서 한 번 틀리면 **새 단서(단어나 메모)를 하나 더 얻을 때까지** 다시 고를 수 없다. 찍기로 넘어가지 못하게. 선택지는 3~5개, 서로 그럴듯하게.
- `photo` 장면은 좌표가 맞아야 하므로 **SVG 로만 그린다** (연필 현장 스케치나 흑백 감식 사진 느낌). 이 그림에는 `prompt` 를 달지 않는다. 찾을 물건은 그림에 실제로 그려 둔다. 관계없는 물건도 몇 개 그려 둔다.
- 대조 세트, 관찰 장면·지점의 `id` 는 사건 안에서 겹치지 않게 (`'#id'` 조건으로 가리킬 수 있다: "지점을 찾았음", "감정이 일치했음").
- 새 방식은 **시대에 맞게**: 1888년 필적 대조·숙박부 조회, 1922년 우유 장부로 날짜 재구성, 1968년 도료 감정, 1991년 성문(목소리) 대조, 2006년 택배 송장 조회, 2014년 차량 번호·하이패스 조회처럼.

공통 속성: `id`, `type`, `name`, `desc`(짧은 안내), `skin`(기본 문서 스킨), `paper`(신문 제호 등 문서 머리글), `need`(탭이 나타나는 조건), `lock`(잠금), `placeholder`, `startLabel`, `empty`.

**잠금** `lock: { code: ['정답', '다른 정답'], label, hint, hint2, desc, title, ok, password: true, need: [...] , keys: [...] }`
- `code` 는 공백·대소문자·문장부호를 무시하고 비교한다.
- `need` 는 **검사기용**이다. 비밀번호를 알아낼 수 있게 되는 조건(단어/사실)을 적는다. 이게 없으면 검사기가 처음부터 풀 수 있다고 본다.
- `hint2` 는 ★3 에서 두 번, ★4 에서 세 번 틀리면 보인다. ★5 에서는 안 보인다. 문서에도 `lock` 을 붙일 수 있다.

**조건(need) 문법** — 배열, 전부 만족해야 한다.
- `'k_단어'` : 그 단어가 수첩에 있음
- `'#id'` : 그 잠금(문서/도구)·암호·재구성을 풀었음, 그 대조 감정이 일치했음, 그 관찰 지점을 찾았음
- `'!f_사실'` : 그 사실이 담긴 메모를 적었음 (증거를 들이밀기)
- `'@분'` : (live 사건만) 수사 시작부터 그만큼 시간이 흘렀음
- `'?rq_id'` : (live) 그 신청서를 올렸음 — 회신 전이어도 (기각된 것은 아님). "공문 올렸습니다" 같은 내 말에.
- `'~조건'` : 그 조건이 **아직 아님** (예: `'~#rq_addr'` 그 회신이 아직 안 왔음). live 사건에서 `at` 과 함께 쓰면 "그 시각까지 못 해냈을 때" 오는 말이 된다. 검사기는 언젠가 참이 될 수 있다고 보고 통과시킨다.

## 4. 단어 (keywords)

```js
k_mary: { label: '메리 켈러', type: 'person', alias: ['메리', '켈러'] },
```
- `type`: `person` 인물 · `place` 장소 · `thing` 물건 · `time` 때 · `word` 기타
- 범인은 반드시 `person`. 보고서의 범인 칸에는 수첩에 적은 `person` 단어만 나온다.
- label/alias 는 검색어와 문서 속 `[[…]]` 를 찾는 데 쓰인다. 겹치지 않게.
- 30~50개 권장. 쓸모없는 단어(동네 이름, 지나가는 사람)도 섞어서 어떤 게 중요한지 티 나지 않게.

## 5. 문서 (docs)

```js
d_star_0901: {
  src: 'star',                       // 소속 도구 id
  title: '벅스 로우에서 여성 숨진 채 발견', meta: '1888년 8월 31일 · 2면',
  kicker: '(선택) 작은 머리말', paper: '(선택) 제호', skin: '(선택) 스킨', cls: '(선택) 추가 class', bar: '(선택) web 스킨 머리띠 색',
  find: ['k_bucks'],                 // archive 전용: 이 단어로 검색하면 뜬다
  need: ['k_x'],                     // 이 조건이 되어야 목록/검색에 나타난다
  lock: { … },                       // (선택)
  body: [ 블록, 블록, … ],
},
```

**블록** — 문자열은 문단. 객체는 아래 중 하나. 모든 텍스트에 `[[단어]]`, `[[보이는 말|k_id]]`, `**굵게**`, `~~지움~~`, 줄바꿈 `\n` 을 쓸 수 있다.

| 블록 | 모양 | 메모 가능 |
|---|---|---|
| `'문장'` / `{ p: '문장', f: 'f_id' }` | 문단 | O |
| `{ h: '소제목' }` | 소제목 | X |
| `{ say: '말', who: '이름', at: '시각', f }` | 진술·녹취 한 줄 | O |
| `{ msg: '말', who: '이름', at: '21:02', me: true, f }` | 말풍선 (me=이 기기 주인) | O |
| `{ rows: [[칸,칸],…], head: [..], cap, f: { 2: 'f_id' } }` | 표. 행마다 메모 가능. f 는 {행번호: 사실} | O (행) |
| `{ list: ['…','…'], f: { 0: 'f_id' } }` | 목록 | O (항목) |
| `{ img: 'art키', cap: '설명', f }` | 그림 + 설명 | O (설명) |
| `{ note: '작은 글씨' }` / `{ stamp: '도장' }` / `{ sign: '서명' }` / `{ divider: '날짜 구분' }` / `{ sep: true }` / `{ cipher: '기호열' }` | 장식 | X |
| `{ m: 'M의 메모' }` | 선배 M의 여백 메모. **사건당 딱 1개**, 도달 가능한 곳에 | X |
| 아무 블록에 `cls: '…'` | CSS class 추가 | |
| 문단에 `nopin: true` | ✎ 없앰 | |

**스킨** (문서 겉모습): `plain` `report`(수사 서류·진술조서) `news`(신문, `cls:'vertical'` 이면 세로쓰기) `letter`(손편지) `telegram`(전보) `ledger`(장부·숙박부·기록표) `card`(증거물 카드) `transcript`(녹취록) `memo`(쪽지) `photo`(사진 인화) `web`(현대 웹) `chat`(메신저) `sms`(폴더폰 문자) `home`(2000년대 미니홈피) `files`(파일 탐색기) `cipher`(해독지).
새 스킨이 필요하면 `css` 에 `[data-case="c01"] .skin-이름 {…}` 로 직접 만든다.

**사실(f)**: 증거가 될 수 있는 블록에 `f: 'f_이름'` 을 단다. 같은 사실을 여러 곳에 달아도 된다(경로가 여러 개면 좋다). 사실이 아닌 블록도 전부 메모할 수 있으니, **f 가 붙은 문장이 튀지 않게** 평범한 문장 사이에 섞는다.

## 6. 탐문 (people)

```js
p_abberline: {
  name: '애버린 경위', role: 'H 분서 형사', where: '커머셜 스트리트 분서', color: '#5a5f78', initial: '애', art: '(선택) 초상 art 키',
  key: 'k_abberline',                // 이 단어가 수첩에 있어야 찾아갈 수 있다 (없으면 처음부터)
  need: [...],                       // (선택) 추가 조건
  intro: ['처음 만났을 때 하는 말', …],   // 블록 배열
  ask: {
    k_bucks: ['그 골목 말이오? …'],     // 수첩 단어 → 대답(블록 배열)
    k_knife: { need: ['!f_apron'], a: ['(증거를 들이밀면 달라지는 대답)'], else: ['(그 전 대답)'] },
  },
  self: ['자기 이름을 물었을 때'],      // (선택)
  idle: ['모르는 걸 물었을 때 하는 말'],   // 그 인물 말투로
},
```
- 조건부 대답(`need` + `a` + `else`): 증거를 들이밀면 말이 바뀐다. 거짓말하는 인물에 쓰면 좋다. 이미 물어본 뒤 조건이 채워지면 그 단어가 빨갛게 "다시 묻기"로 바뀐다.
- 인물 4~7명. 용의자 2명 이상 + 목격자·주변인. **범인도 탐문 대상이면 좋다** (거짓말이 기록과 어긋나게).
- 탐문은 **대화 말풍선**으로 그려진다. 형사의 질문은 단어 종류(인물·장소·때·물건·기타)에 맞춰 엔진이 만들고, 대답은 한 줄이 말풍선 하나다.
  - 줄 맨 앞 `(…)` 는 몸짓으로 따로 찍힌다: `'(대패를 내려놓는다) 은천에서 여기까지 오셨소.'`
  - 줄이 `— ` 로 시작하면 **형사가 끼어든 말**(오른쪽 말풍선): `'— 토요일 아침 여덟 시 반에요?'`
  - 몸짓만 있는 줄(`'(대답하지 않는다)'`)은 침묵으로 보인다.
- 번복 대답(`need` 가 있는 것)은 추궁 장면이 된다: 북소리 → 형사의 추궁 한마디 → 조건에 걸린 **수첩 메모를 내미는 장면** → 침묵 → 대답. 이 대답에만 목소리가 붙는다 (`tools/voices.js` 의 `CAST` 에 그 사람 목소리를 정해 두면, 첫 말풍선은 그 사람 목소리, `— ` 줄은 주인공 목소리, 그 뒤 대꾸는 다시 그 사람 목소리).
- 새 인물을 넣으면 `tools/voices.js` 의 `CAST` 에 `'사건/인물': [말소리 높이 Hz]` 한 줄을 더한다 (목소리를 붙일 사람은 `[높이, 목소리, 빠르기, 안정도]`). 빠지면 기본 높이로 찍힌다.

## 7. 정답 (solution)

```js
solution: {
  culprit: 'k_범인',
  claims: [
    { id: 'c1', q: '범인이 그날 밤 그곳에 있을 수 있었다', accept: ['f_a', 'f_b'] },
    { id: 'c2', q: '…', accept: ['f_c'] },
    { id: 'c3', q: '동기', accept: ['f_d', 'f_e'] },
  ],
  near: '(선택) 하나 틀렸을 때 문구', far: '(선택) 여럿 틀렸을 때 문구',
  stamp: '1888.11.30 · H 분서',       // 종결 도장에 찍히는 날짜
  epilogue: ['종결 뒤에 나오는 진상 서술', …],
  next: '(선택) 다음 사건으로 이어지는 한 줄',
},
```
- claims 는 3~4개. **질문(q)에 답을 흘리지 않는다.** 좋은 예: 「그 시각 그 장소에 있었다」, 「범인만 알 수 있었던 것」, 「피해자와의 연결」, 「동기」. 나쁜 예: 「범인이 가짜 경찰 제복을 입었다는 증거」.
- accept 에는 그 주장을 뒷받침하는 사실을 2개 이상 두는 게 좋다 (한 경로가 막혀도 풀 수 있게).
- 검사기가 계산하는 **추적 깊이**(정답 증거까지 몇 단계를 거쳐야 하는지)가 **4~6** 이 되게 설계한다.

## 8. 그림 (art) 과 이미지 프롬프트

모든 그림은 먼저 **SVG 로 가볍게** 그린다(게임이 바로 돌아가도록). 나중에 사람이 AI 로 진짜 이미지를 만들면 `img/사건id/키.webp` 로 넣어 자동 교체된다.

```js
art: {
  cover: { use: '기록실 폴더에 클립으로 끼운 사진', ratio: '4:3', svg: '<svg viewBox="0 0 200 150">…</svg>', prompt: 'English prompt …',
          must: '(선택) 꼭 보여야 할 단서', avoid: '(선택) 주의점', redo: { level: '필수', why: '(검수 뒤) 다시 뽑을 이유' } },
  map: '<svg …>…</svg>',              // 문자열이면 프롬프트 없는 SVG 전용 (지도·도면처럼 좌표가 중요한 것)
}
```
- `cover` 는 필수 (기록실 폴더 표지).
- `must` 는 그 그림이 단서일 때 꼭 보여야 할 것 (색·개수·방향). 본문·캡션과 어긋나면 안 된다. 흑백 사건에서 색이 단서면 프롬프트에도 "hand-tint only …" 를 적는다.
- 검수에서 걸린 그림에는 `redo: { level: '필수'|'선택', why }` 를 달면 `docs/IMAGE_REDO.md` 에 모인다. 프롬프트는 `docs/IMAGE_PROMPTS.md` 맨 위 「생성 규칙 v2」 를 따른다 (가짜 글자·창밖 풍경·삽입 칸 금지 등).
- 문서 속 사진·삽화·증거물·초상 등 **이미지가 들어갈 자리는 전부** `prompt` 를 단다. 사건당 **8~16장** 정도.
- SVG: `viewBox` 필수, 외부 링크·스크립트 금지, 한 장 3KB 안팎. 단순한 도형과 그 시대 색으로.
- `prompt` 는 **영어**로, 구체적으로 (피사체, 구도, 시점, 조명, 재질, 시대 고증, 카메라/인쇄 방식). **글자는 넣지 않는다**("no readable text"). 실제 인물 얼굴 금지, 시신·피·상처 묘사 금지, 실제 상표 금지. 사람은 뒷모습·실루엣·흐릿한 인물 정도로.
- 지도·약도·도면을 그림으로 바꿀 때는 `labels: [['이름', x%, y%, 'l'|'c'|'r'], …]` 를 달고 그림에는 글자를 넣지 않는다. 이미지가 들어오면 엔진이 이름표를 그 자리에 얹는다 (y 는 글자 밑줄 위치). 지도 위 단서 점(`spots`)·사진 속 찾을 곳의 x·y 도 새 그림에 맞춰 옮긴다.
- `made: true` 는 프롬프트 없이 직접 만드는 그림 (c08 성문 스펙트로그램처럼 계산으로 그린 것).
- `artStyle` 은 사건 공통 그림체 한 문단 (영어). 시대별 예:
  - 1880년대: 19th-century newspaper wood engraving / cross-hatched ink illustration
  - 1920년대: silver gelatin photograph, heavy grain, sepia toning, soft vignetting
  - 1930년대 경성: 1930s Korean newspaper halftone photograph, coarse dot screen, faded
  - 1960~70년대: 1960s-70s 35mm film photo, Kodachrome/Tri-X look, slight color shift
  - 1990년대: early 1990s compact camera photo, date-stamp-free, flash, film grain
  - 2006년: 2006 compact digital camera, 3-megapixel, slight noise, flat flash lighting
  - 2014년: early smartphone photo / dashcam still, compression artifacts

## 9. 시대와 소재 — 지켜야 할 것

- 실제 미제 사건은 **모티프만** 빌린다. 이름·장소(가상 지명)·날짜·수법·결말을 바꾼다. 원래 사건의 실존 피해자 이름, 실존 용의자 이름, 실존 수사관 이름을 쓰지 않는다.
- 진범은 **완전히 지어낸 인물**이다. 실존 인물(유명한 용의자 포함)을 범인으로 암시하지 않는다.
- 보통 사건은 폭력을 화면 밖에 둔다. 기록은 건조하게("숨진 채 발견", "머리에 둔기에 의한 상처"). 시신은 **가리거나 암시**해서 공포감만 만든다 (덮인 시트, 그림자, 현장 테이프, 빈 신발 한 짝).
- **잔혹한 사건**(토막 살인, 시신 훼손 등)은 `graphic: true` 로 표시하고 `warn` 에 무엇이 들어 있는지 적는다. 현장의 잔혹함이 **느껴지게** 쓴다 — 다만 말투는 검안서·감식 기록·신문 기사의 것으로: 어떤 부위가 어디서 어떤 상태로 발견됐는지, 절단면이 무엇을 말하는지(도구, 솜씨, 시각), 혈흔 형태 분석(비산흔·낙하흔·닦아낸 흔적·전이흔), 루미놀 반응. 고통을 늘어놓거나 즐기듯 쓰지 않는다.
  - 화면: 엔진이 책상 가장자리와 일부 문서에 **마른 핏자국**을 얹는다. 문서마다 `blood: 'heavy'`(감식 사진철·현장 검증 조서처럼 핏자국이 많은 기록) / `blood: true`(한두 점) / `blood: false`(깨끗한 신문 스크랩 등)로 조절한다. 플레이어는 「잔혹 표현」 단추로 끌 수 있다.
  - 그림: 빨간 별 값을 하도록 **범행 흔적은 진하게** — 벽의 비산흔, 바닥의 낙하흔, 호 모양으로 닦아 낸 자국, 줄눈·배수구에 스민 피, 피가 밴 포대·봉투, 루미놀 암실 사진. 시신은 **가려진 채 일부까지** — 방수포·포대 밖으로 나온 손이나 아래팔, 비닐 너머 비치는 팔다리 윤곽, 매듭에 걸린 머리카락, 천 아래 여러 덩어리로 놓인 형체. 절단면·내부 장기·상처·죽은 사람의 얼굴은 넣지 않는다 (생성 AI 도 거절하고, 실제 사건 모티프의 피해자를 떠올리게 한다). 무서움은 보여 주는 양보다 **본문과 맞아떨어지는 구체성**에서 나온다 — 캡션이 「비산흔 수십 점」이면 그림에도 수십 점. 이런 그림의 art 에는 `sensitive: true` 를 붙인다 → 게임에서 흐리게 가려진 채 「열람 주의 · 눌러서 보기」로 나온다.
  - SVG 현장 스케치에도 마른 핏자국(#5a130c~#7a1c12, 불규칙한 얼룩·낙하흔·끌린 자국)을 그려도 된다.
- 성범죄는 어떤 사건에서도 쓰지 않는다. 아이를 피해자로 만들지 않는다. (graphic 사건도 같다.)
- 외국 사건의 문서는 **한국어 번역본**으로 쓰되, 제호·도장·서명 같은 곳에 원어를 살짝 남기면 분위기가 산다 (예: 제호 `The East End Star`, 독일 도장 `Gendarmerie`). 시대 말투를 살린다 (1930년대 신문체, 1970년대 수사 서류체, 2006년 미니홈피 말투).
- 그 시대에 **없는 것을 쓰지 않는다** (1922년에 전화 기록 조회, 1991년에 휴대폰 문자 등).

## 10. 분량과 품질 목표 (본 사건 기준)

- 플레이 25~40분. 문서 20~32개, 인물 4~7명, 단어 30~50개, 사실 14~24개.
- 조사 도구 3~5개. 그 시대에만 있는 도구를 최소 하나 (전보, 숙박부, 전화교환 기록, 삐삐 음성사서함, 미니홈피 방명록…).
- **추적 사슬**: 개요 → (검색) → 이름 하나 → (탐문) → 장소 → (다른 자료실) → … 식으로 단서가 단서를 열게. 모든 걸 첫 화면에서 볼 수 있으면 실패.
- **그럴듯한 가짜 용의자** 1~2명. 수상한 기록이 있지만 다른 기록이 그를 풀어 준다(알리바이).
- **엇갈리는 기록**: 누군가의 진술이 다른 기록(시각표, 장부, 날씨, 우편 소인…)과 어긋나는 지점이 진상의 열쇠가 되게.
- 암호·비밀번호·지도는 양념. 그것만으로 풀리게 하지 않는다.
- M의 메모 1개: 그 사건의 **조사 방법**에 대한 짧은 혼잣말(40자 안팎). 답을 알려 주지 말 것. 예: 「소인은 편지가 거짓말할 때도 진실을 말한다.」

## 11. 난이도 (stars) — ★3 부터 ★5 까지

별은 폴더와 수첩에 붙는다. `graphic: true` 면 별이 빨갛다. 난이도는 **엔진 규칙**과 **내용** 두 쪽에서 달라진다.

| | ★3 | ★4 | ★5 |
|---|---|---|---|
| 보고서가 틀렸을 때 | 어긋난 칸을 알려 준다 (범인, 2번…) | 한 칸 틀림 / 여러 칸 틀림만 | "반려" 한 마디 (`far` 문구) |
| 잠금 hint2 | 2번 틀리면 | 3번 틀리면 | 없음 |
| 암호 | 맞은 기호 개수 | 맞은 기호 개수 | 개수 안 알려 줌 |
| 재구성 | 제자리 카드 표시 + 개수 | 개수만 | "앞뒤가 맞지 않는다"만 |
| 대조 감정 | 한 번 틀리면 hint, 바로 다시 | 두 번 틀리면 hint, 틀리면 새 단서 필요 | hint 없음, 틀리면 새 단서 필요 |
| 탐문 "다시 물어볼 만함" 표시 | 있음 | 있음 | 없음 (스스로 떠올려야 한다) |
| 관찰 "찾은 것 n / 전체" | 전체 수 보임 | 전체 수 보임 | 찾은 수만 |

내용 목표:
- **★3** — 추적 깊이 4 안팎. 가짜 용의자 1~2명. claim 마다 인정 증거 3개 이상. `scrawl`·문서 속 메모가 방향을 넌지시 짚어 준다. 새 조사 방식 1개.
- **★4** — 추적 깊이 5. 가짜 용의자 2명, 거짓말하는 인물 1명 이상(증거를 들이밀어야 말을 바꿈). 인정 증거 2~3개. 새 조사 방식 1~2개.
- **★5** — 추적 깊이 6 이상, 인물 6명 이상. 가짜 용의자 2~3명 (그중 한 명은 거의 범인처럼 보이게). 범인 이름은 늦게(4라운드 이후) 드러난다. 인정 증거 2개씩, 흔한 메모로는 안 되게. 안내 메모는 줄이고, 기록끼리 맞대 봐야 보이게. 새 조사 방식 2개 이상.

## 12. 사건의 공기 (mood)

사건을 열면 화면 전체에 그 시대·장소의 공기가 깔린다 (`js/mood.js`, `css/mood.css`). 서류 위에 얹되 가운데 읽는 자리는 비워 두고 가장자리에서만 짙어진다. 폴더를 눌러 열 때는 `line` 한 줄이 적힌 여는 장면이 3초쯤 떴다가 사라진다 (누르면 바로 넘어감).

```js
mood: { light: 'lamp', fx: 'dust', amb: ['clock', 'clapper'], line: '소화 10년 11월, 종로 뒷골목. 밤이 깊으면 야경꾼 딱딱이 소리만 남는다.' },
```

| 항목 | 고를 수 있는 것 |
|---|---|
| `light` 조명 빛깔 | `gas` 가스등 · `lamp` 백열등·등잔 · `cold` 겨울 낮빛 · `sea` 바닷가 청록 · `rain` 비 오는 날 회청 · `sodium` 나트륨 가로등 · `screen` 모니터 불빛 · `fluoro` 형광등 |
| `fx` 날씨 | `fog` 안개 · `mist` 물안개 · `steam` 김 · `smoke` 담배 연기 · `rain` 비 · `drizzle` 가랑비 · `snow` 눈 · `dust` 불빛 속 먼지 |
| `amb` 배경음 (여럿) | `rain` `drizzle` `wind` `surf`(파도) `harbor`(항구 물결) `river` `city`(먼 차 소리) `clock` `clapper`(딱딱이) `bell`(먼 종) `horn`(뱃고동·무적) `hum`(전기 웅웅) `fan`(컴퓨터 팬) `room` `drip`(물방울) `drone`(빨간 별 사건 전용, 잔혹 표현을 끄면 빠짐) |
| `line` 여는 글 | 한두 문장. 시기·장소·첫 감각만. 범인이나 풀이의 실마리는 넣지 않는다 |

- 배경음은 모두 합성음이라 파일이 없다. 「소리 켜짐」일 때만 나고, 탭을 떠나면 멈춘다.
- 기기에서 움직임 줄이기를 켜 두면 날씨가 멈추고 여는 장면은 짧게 지나간다.
- `node tools/validate.js` 가 이름을 검사한다. `mood` 가 없으면 경고.

## 13. 실시간 수사 (live) — 지금 벌어지는 사건

과거의 기록을 뒤쫓는 대신 **지금 막 벌어진 사건을 직접 수사**한다. 2020년대 사건(`frame: 'laptop'`)에 쓴다. 최소 예시: `docs/examples/live-example.js`

```js
live: {
  start: [2024, 3, 8, 22, 40],        // 수사가 시작되는 때 [년, 월, 일, 시, 분]
  deadline: { at: 2880, label: '체포 후 48시간', who: '팀장', miss: '48시간이 지났다. 일단 풀어 준다.' }, // (선택) 수사 시작부터 몇 분 뒤
  cost: { ask: 20 },                  // (선택) 행동마다 흐르는 분 — 기본 doc 8 · ask 15 · search 4 · query 12 · compare 40 · timeline 10 · photo 6 · write 20
},
```

**시계** — 문서를 처음 읽기, 탐문(처음 묻는 것), 검색, 조회, 감정, 신청서 쓰기에 시간이 든다. 화면 아래 줄에 `D+n 3.8(금) 22:40` 과 기한까지 남은 시간이 보이고, 기다릴 것이 있으면 「회신 기다리기 · 45분」 단추가 뜬다. 조건에 `'@분'` 을 쓰면 **그 시각이 지나야** 열린다 (`need: ['@600']` = 수사 시작 10시간 뒤). 검사기는 시간은 언젠가 흐른다고 보고 통과시킨다.

**영장·공문 신청 (`type: 'request'`)** — 플레이어가 수사를 이끄는 도구. 신청서를 골라 **소명 자료(수첩 메모 하나)**를 붙여 올리면, 맞는 근거면 접수되고 `eta` 분 뒤에 회신 문서가 온다. 틀린 근거면 기각된다 (★5 는 다시 쓰는 데 60분이 더 든다).

```js
{ id: 'rq', type: 'request', name: '영장·공문', empty: '아직 신청할 근거가 없다.', items: [
  { id: 'rq_car', kind: '차량 조회', title: '차량 소유자 조회 요청', meta: '(선택)',
    to: '관할 차량등록사업소', target: '[[흰 승합차]]', what: '소유자 인적사항', by: '(선택, 기본 강력2팀)',
    intro: ['(선택) 신청서 위에 적힌 블록'],
    need: ['k_plate'],                // 신청서가 나타나는 조건
    why: ['f_plate'],                 // 소명으로 인정되는 사실들. 없으면 근거 없이 바로 접수 (협조 공문 등)
    deny: '번호판이 확인된 근거가 없다.', // 기각 사유
    eta: 180,                         // 회신까지 분
    doc: 'd_owner',                   // 회신 문서 (docs 에 src: 'rq' 로 둔다)
    keys: ['k_x'],                    // (선택) 회신이 오면 수첩에 적히는 단어
    feed: { who: '막내', msg: '차주 나왔습니다.', src: '(선택) 단톡방 id' }, // (선택) 회신 알림 문구 — 단톡방에도 한 줄 남는다
  },
] },
```
- 회신 문서의 `src` 는 그 request 도구 id. 회신이 오기 전에는 어디에도 안 뜬다. 조건에서 `'#rq_car'` 는 "그 회신이 왔음".
- 영장이 **기각될 수 있어야** 재미있다: 수첩에 비슷해 보이지만 소명이 안 되는 메모(소문, 추측, 다른 차 번호)가 있게.
- 시대 고증: 통신사실확인자료 제공요청(법원 허가), 압수·수색·검증영장, 금융거래정보 제공요청, CCTV·블랙박스 임의 제출, 택배·배달앱 협조 공문, 가상자산 거래소 협조 요청, 디지털 포렌식 의뢰(모바일 이미징), 국과수 감정(마약 성분·필적·DNA)… 회신까지 걸리는 시간도 그럴듯하게 (CCTV 한두 시간, 통신 조회 반나절~하루, 국과수 며칠 → 사건 안에서는 줄여도 된다).

**팀 단톡방 (`type: 'feed'`)** — 동료·팀장·제보자의 말이 **시간이 흐르거나 조건이 채워지면** 새로 온다. 새 말이 오면 화면 위에 휴대폰 알림이 뜬다.

```js
{ id: 'room', type: 'feed', name: '팀 단톡방', title: '강력2팀 (4)', kicker: '메신저', skin: 'chat', items: [
  { id: 'm1', at: 0, who: '팀장', msg: '현장 CCTV부터 확보해.', keys: ['k_owner'] },   // at: 수사 시작 몇 분 뒤
  { id: 'm3', need: ['#rq_cctv'], who: '막내', msg: '번호판 찍어 올립니다.', doc: 'd_plate', att: '사진 1장' }, // 첨부 문서 (docs 에 src: 'room')
  { id: 'm5', need: ['!f_plate'], me: true, msg: '차주 조회 넣었습니다.' },          // me: 주인공이 보낸 말
  { id: 'm6', at: 600, who: '팀장', msg: '…', f: 'f_hint' },                        // 말 자체도 메모할 수 있다
] },
```
- `at` 과 `need` 가 **둘 다** 채워지면 온다. 조건이 `at` 보다 늦게 채워지면 그때 시각으로 찍힌다 — 본문에 시각이 적힌 말은 `backdate: true` 로 `at` 시각에 고정한다. 온 말은 `'#말id'` 조건으로 가리킬 수 있다. 단톡방은 수사를 앞으로 미는 장치다 — 새 단어를 주고, 증거를 들이밀 때 동료가 반응하고, 기한이 다가오면 압박한다. 정답을 말해 주지는 않는다.

**기한과 늦은 결말** — `deadline.need` 가 있으면 그 조건이 채워진 뒤에야 화면 아래에 기한이 보인다 (스포일러 방지. 기한 자체는 처음부터 흐른다). `deadline.at` 을 넘기면 알림이 오고, 그 뒤에 보고서를 맞히면 `solution.late` 결말이 나온다 (예: 구속영장 기한을 넘겨 풀어 줬다가 다시 잡았다). 기한을 넘겨도 사건은 풀 수 있다 — 벌이 아니라 결말의 온도가 달라진다.

**결말의 시각** — live 사건의 `epilogue`·`late` 문장에 `{{t}}`(예: 15:40) 나 `{{d}}`(예: 11월 22일(금) 15:40)를 쓰면 보고서를 올린 시각으로 바뀐다.

**보고서 서식** — `solution.form` 으로 보고서 이름과 문구를 바꾼다: `{ title: '구속영장 신청서', culprit: '피의자', short: '피의자', submit: '영장 신청', open: '신청서 쓰기', lead: '…', judging: '신청서를 올렸다. 검사가 읽는다…' }`.

**live 사건 쓰는 법**
- 첫 화면은 **신고 접수·출동 지령**이다. 사건은 과거가 아니라 지금 — 기록은 수사가 만들어 내는 것(신청서 회신, 포렌식 결과, 동료의 보고)이 절반 이상이게.
- 시간이 이야기를 만든다: 피해자가 병원에서 깨어나는 시각, 증거가 지워지는 시각(자동 삭제되는 CCTV·메신저), 용의자가 출국하는 시각을 `@분` 과 단톡방으로 건다.
- M 의 메모는 두지 않는다 (M 은 이미 떠났다). 기록실에서는 「당직 · 현행 사건」 칸에 따로 꽂힌다.
- 민감한 소재(마약, 청소년 범죄, 스토킹·교제폭력, 디지털 범죄)는 **피해의 무게를 가볍게 다루지 않는다**: 가해를 멋있게 그리지 않고, 수법은 수사 기록의 건조한 말투로, 피해자에게는 이름과 삶을 준다. 성범죄와 아이 피해자는 여기서도 쓰지 않는다 (9절). 청소년이 나오면 가해·이용하는 쪽은 어른이고, 청소년은 이용당하거나 가담한 쪽으로 — 소년법 절차(소년부 송치, 보호자 동석)를 지킨다.
